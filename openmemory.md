# OpenMemory Guide — Workxpace

## Overview
Workxpace is the HCFI eBudgeting app (Next.js App Router, Prisma, NextAuth). Protected routes live under `app/(protected)/`. Authorization is per-user JSON on `UserAccess` (`menuAccess` + `activityAccess`), not role-menu matrices.

## Architecture
- **Session:** `lib/auth/session-user.ts` builds JWT claims. `ADMIN` role starts from `fullMenuAccess` / `fullActivityAccess`; other roles start from defaults. Stored `UserAccess` JSON overrides the baseline.
- **Department RLS (documents):** `lib/access/cross-department.ts` — `viewOtherDepartmentDocuments` / `createForOtherDepartment`.
- **Department RLS (dashboard):** `lib/access/dashboard.ts` — `viewAllDashboardDepartments`. Independent from document RLS.
- **Dashboard personas:** `activityAccess.dashboardView` = `department` | `director` | `fpa`. Assigned per user on Access Control. Runtime view is locked (no switcher).
- **Dashboard data:** `GET /api/dashboard/summary` aggregates `DataMartStagingRow` plus outstanding GR (approved BR vs paid) and pending PR. Formulas: `lib/dashboard/metrics.ts`.

## Components
- `lib/budget-plans/form.ts` — Budget Plan form values, allocation helpers, and required-field validation (`validateRequiredBudgetPlanWriteFields` / `validateBudgetPlanForm`). Supporting Documents are the only optional field on create/edit.
- `lib/budget-plans/code.ts` — Budget Plan document-code allocator (`allocateNextBudgetPlanCode` / `createBudgetPlanCodeAllocator`). Sequence is MAX(existing suffix)+1, not COUNT (COUNT collides when the same `{DEPT}{YYYY}{MM}` prefix has gaps).
- `lib/budget-plans/bulk-import-template.ts` — Builds the BP bulk-import XLSX. Download is `GET /api/budget-plans/bulk-import/template` so the sample row uses live Origin Office / Department / Project / Approval Schema codes (static `public/templates/...xlsx` is a fallback).
- `lib/approval-schema-usage.ts` — Counts BP/BR/PR still linked to an approval schema; blocks delete while open documents (`Draft`/`Pending`/`Reviewed`/`Revision`) use it
- `lib/approval-schema-usage.ts` — Counts BP/BR/PR still linked to an approval schema; blocks delete while open documents (`Draft`/`Pending`/`Reviewed`/`Revision`) use it
- `lib/fiscal-year.ts` — Calendar FY helpers. Selectable years on create/filter/report dropdowns are **N and N+1 only** (`getSelectableFiscalYears`). `FiscalYearSelect` / `FiscalYearFilter` read from this file; list "All years" still finds historical docs without listing old years as options.
- `lib/auth/password.ts` — Shared credentials password rules (`MIN_PASSWORD_LENGTH`, `validateChangePasswordInput`) used by Profile Change Password and User Management
- `app/(protected)/dashboard/page.tsx` — server wrapper via `renderClientPage` (Next 15 params Promise must not reach the client)
- `app/(protected)/dashboard/PageClient.tsx` — locked persona shell + filters
- `components/dashboard/*` — reusable KPI/chart/table widgets (SOLID: one visual per file). `DashboardProportionDonut` is Actual vs Remaining against Total Budget; Department monthly comparison uses `DashboardGroupedBar` with Budget / Realisasi / Sisa Anggaran. Grouped-bar columns must `h-full`/`items-stretch` so percentage bar heights resolve against the plot area.
- `DepartmentDashboard` / `DirectorDashboard` / `FpaDashboard` — compose widgets from the spec
- `components/ui/SegmentedControl.tsx` — reusable All/Q1… switcher; dashboard quarter filter uses All | Q1 | Q2 | Q3 | Q4 (calendar FY has no Q5)

- `components/reports/BudgetPivotTable.tsx` — Budget Pivot presentation. Hierarchy includes **BR No** (link via `BudgetRequestCodeLink`) immediately before Description. Aggregation in `lib/data-mart/budget-pivot.ts`; XLSX in `lib/data-mart/budget-pivot-export.ts`.

## Patterns
- **BP document codes:** `{DEPT}{YYYY}{MM}{seq}` e.g. `IT202608001`. Shared helper `lib/budget-plans/code.ts` — form create (`POST /api/budget-plans`) and bulk import (`/api/budget-plans/bulk-import`) must use the same allocator. Sequence is the highest existing suffix + 1 (not a row COUNT — gaps from deleted drafts make COUNT reuse a live code and Prisma P2002 on `code`). Do **not** mint `BP-00001` from trailing digits of the latest row. Bulk-imported rows are flagged with `importedViaBulk`, not a separate code prefix. Unique collisions retry up to 3 times; API errors must not dump `Invalid prisma.budgetPlan.create()`.
- **BP bulk-import template:** Columns are `lib/budget-plans/bulk-import-columns.ts`. Sample row must use master **codes** (Origin Office `99` = HEAD OFFICE, schema e.g. `BP-PRIMARY` or production `BP-TESTING-ALLDEPT`), not dummy `SG` / `A1`. Download Template hits the live-data API so the sample matches this environment. Sheet "Instructions" documents the rules; parser prefers sheet named "Budget Plans".
- **Approval schema delete:** `DELETE /api/workspace-management/approval-schema/[id]` refuses with 409 if any open BP/BR/PR still references the schema (and also if closed documents still hold the FK). Do not delete `approval_levels` first — they cascade from the schema; deleting them first then failing the schema delete leaves documents without approval info.
- **Approval schema snapshot:** BP/BR/PR store `approvalSchemaSnapshot` JSON at create/update (and bulk import). Review, approve, comments, and notifications resolve levels via `approvalLevelsOf` / `withFrozenApprovalSchema` (snapshot first, live schema only if missing). Changing the master schema only affects new documents or drafts that pick a *different* schema. Existing rows were backfilled in migration `20260902143000_approval_schema_document_snapshot`.
- **Profile change password:** Logged-in users change their own credentials password on `/profile` via `POST /api/profile/password`. Requires current password, new password ≥ 6 chars, and matching confirmation. Hash with bcrypt (cost 10), same as User Management. Do not log the password — activity history only records `{ passwordChanged: true }`.
- **Budget Request required fields:** Create/edit require Department, Project, Description, Notes, and at least one Supporting Document (plus existing Subject / schema / months / items). Shared check `validateRequiredBudgetRequestWriteFields` in `lib/budget-requests/form.ts` is used by `validateBudgetRequestForm` and `POST`/`PUT /api/budget-requests`. Attachments use `validateRequiredSupportingDocs` in `lib/supporting-docs.ts` (existing URLs + pending files). Description uses `isRichTextEmpty`. Project has no blank `-` option. Prisma `projectId` / `description` / `notes` / `supportingDocs` stay nullable so old rows still load; saving now requires them.
- **Budget Plan required fields:** Create/edit require every form field except Supporting Documents. Shared check `validateRequiredBudgetPlanWriteFields` in `lib/budget-plans/form.ts` is used by `validateBudgetPlanForm` and `POST`/`PUT /api/budget-plans`. Description is empty if rich-text has no text/images (`isRichTextEmpty` in `lib/utils.ts`). Project `SearchableSelect` has no blank `—` option and is not preselected on create — user must pick one. Prisma `projectId` / `description` stay nullable so old rows still load; saving now requires both. Supporting Documents stay optional (label says so). BR and PR still require at least one attachment.
- **Payment Request required fields:** Create/edit require Budget Request, Project, Description, Notes, and at least one Supporting Document (plus existing Subject / Payee / Vendor Invoice No / Date Needed / schema / items). Shared check `validateRequiredPaymentRequestWriteFields` in `lib/payment-requests/form.ts` is used by `validatePaymentRequestForm` and `POST`/`PUT /api/payment-requests`. Attachments use `validateRequiredSupportingDocs` (existing URLs + pending files). Description uses `isRichTextEmpty`. Only Approved BRs appear in the picker. When linked, FY / origin office / department / project copy from the BR; if the BR has no project the user must pick one. Prisma `budgetRequestId` / `projectId` / `description` / `notes` / `supportingDocs` stay nullable so old rows still load; saving now requires them.
- **Payment Request required vendor fields:** Create/edit require Vendor Invoice No and Date Needed. Marked with `*` + `required` on `PaymentRequestForm`. Shared check `validateRequiredVendorInvoiceFields` in `lib/payment-requests/form.ts` is used by the form validator and `POST`/`PUT /api/payment-requests`. Columns remain nullable in Prisma so existing rows without values still load; saving a draft now requires both fields.
- **Payment Request required bank fields:** Create/edit require Bank Name, Bank Account, Currency, and Payment purpose. Marked with `*` + `required` on `PaymentRequestForm`. Shared check `validateRequiredPaymentBankFields` in `lib/payment-requests/form.ts` is used by `validatePaymentRequestForm` and `POST`/`PUT /api/payment-requests`. Prisma `bankName` / `bankAccount` / `paymentPurpose` stay nullable so old rows still load; saving now requires them. Currency defaults to `IDR` and is read-only.
- **Selectable fiscal years:** Create/filter/report pickers show only current year (N) and next (N+1), computed in `lib/fiscal-year.ts` — not from the FiscalYear master table (so N+1 appears even if unseeded). List filters keep **All years** for historical documents. Edit of an existing doc may keep its old year in the dropdown so the value stays valid. Create/import APIs reject years outside N/N+1; update may keep the document's existing year or a linked parent BP/BR year.
- **Production build:** `prebuild` clears `.next` before `next build`. Stale Next 15 cache can leave incomplete `app-paths-manifest.json` and surface as `PageNotFoundError` / ENOENT for routes that exist (seen on `/budget-requests/[id]` and `/budget-requests/[id]/review/detail`).
- New activity flags go on `ActivityAccess` + `defaultActivityAccess` + `fullActivityAccess` + `mergeWithDefaultActivityAccess`. JSON column; no Prisma migration for new keys.
- Dashboard widget lists are **not** per-user checkboxes. Persona is a single enum; layout is hardcoded per persona.
- Dashboard department charts merge staging rows that share the same display name (legacy null `departmentId` vs master id) so utilization is one bar per department. List widgets use index-suffixed React keys. Budget-alert ids also include department name + index because the same `departmentId` can appear under more than one staging name.
- Staging `expenseCategory` (and other BR classification fields) often store CategoryMaster IDs, not names. Dashboard charts, alerts, and category filters resolve ID → name via `lib/data-mart/resolve-classification-labels.ts` (same read-time map as reports). Filter queries match both ID and name.
- **Sidebar logo settings:** Application Settings (`/settings`) stores `sidebarLogoUrl` and `sidebarLogoCollapsedUrl` in `application_settings`. Empty = default Workxpace logos (`public/workxpace-full-logo.svg` / `public/workxpace-logo.svg`). Uploads use supporting-docs storage with scope `branding` (PNG/JPG/WebP/SVG, max 2MB). Sidebar reads GET `/api/application-settings` and falls back if the custom URL fails to load.
- **Budget Pivot BR No:** Leaf identity includes `budgetRequestId` so two BRs that share description / GL / CKI are not summed into one row. Column sits immediately before Description; the code links to `/budget-requests/[id]`. Shared headers live in `PIVOT_HIERARCHY_HEADERS` so the table and XLSX export stay aligned.
- **Budget Pivot BR amounts:** The Budget Request section uses `BudgetRequestAllocation` months (once per BR), not staging `expectedAmount`. BR save copies grand total onto every selected month (`normalizeBudgetRequestBody`); the pivot splits that total evenly across those months (`spreadCopiedGrandTotalAcrossMonths`) so FY equals the BR total. Example: BRACT202606003 allocated Jul–Sep at 8.720.000 each → ~2.906.666 per month.
- **Budget Request list Alokasi:** Column immediately before Actions on `/budget-requests`. `GET /api/budget-requests` returns `allocationMonths` (months with allocation > 0). Cell shows `FY {fiscalYear}` plus month labels (`All months` when all 12).
- **Confins employee role sync:** Map from `JobTitleName` only — `roleName` = title as-is; `roleCode` = slug via `generateRoleCodeFromJobTitle` (e.g. `IT_NETWORK_INFRASTRUCTURE_OFFICER`). Same title shares one role. Empty title keeps existing `users.roleId`. Confins `RoleName` is ignored (shared across different titles). Note: `roleId` also drives Approval Schema PIC lookup.
